# 一个告警事件保持唯一处置任务，交付与恢复分别判断

为避免重复通知及跨群通知导致并行修复，同一告警源中的同一个告警事件复用已有任务，通知追加为证据；不凭服务名或文本相似度自动合并。跨群通知关联原任务，由原任务所属群决策，其他群查看进度。

创建 MR 后继续跟进，直到当前代码版本的 Agent 审查和约定的必需检查全部通过，才标记修复交付完成。新提交使旧版本的通过结果失效；检查失败继续处理，权限或外部条件限制则明确阻塞；线上恢复独立展示，不从交付完成推断。

无需代码修复时，将结论、证据及后续建议推送至原任务群并 @ Owner，等待明确确认后关闭，不因超时自动关闭。需要外部处理的任务标记为阻塞，不能将无人回应视为问题已解决。

修复交付完成后，原 MR 收到明确要求修改的意见，或当前代码版本的必需检查失败时，重新打开原任务继续处理；普通讨论不触发。实质扩大方案时仍重新通知并计时，已记录的暂停或拒绝不会因新反馈自动解除。worktree 已清理则从原任务分支恢复，沿用原 MR；已合并或关闭的 MR 不自动续跑。跨 MR 冲突仍由 Owner 协调，不因检查失败自动引入跨任务修复协调。
