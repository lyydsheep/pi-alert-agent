# 首版面向一个业务大仓，跨服务协作在 MR 阶段进行

当前所有业务服务位于同一个仓库，首版固定目标业务大仓，不引入服务到仓库的映射管理。这里的大仓指 Agent 处理的业务仓库，不改变 pi-alert-agent 自身的单上下文文档布局。

调查阶段允许查询日志和 Trace、读取源码，以及在任务独立 worktree 和临时目录中运行测试与临时复现脚本；临时文件不进入交付补丁，生产写操作需要另行授权。首版工作区分离不代表宿主权限隔离。

根因涉及同一业务大仓中的 B 服务时，允许修复 B 的代码，不以 B 的 Owner 事先批准为前提。创建 MR 后在原任务群通知 A 的 Owner，由其联系 B 的 Owner 共同查看 MR 和告警问题。

跨服务修改仍遵循原任务群的方案等待规则：方案明确涉及的其他服务，提醒当前 Owner 协调相关服务的 Owner，经过明确同意或完整的限时异议流程后执行。执行中发现需要实质扩大修改范围时，更新方案并重新通知、计时。

创建 MR 后完成给原任务群的协作通知；相关服务 Owner 的额外人工评审不作为 Agent 的交付完成条件，仓库已有的必需审批除外。修复交付完成仍要求当前 HEAD 的 Agent 审查和约定的必需检查全部通过。
