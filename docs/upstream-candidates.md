# Pi / Phoenix 上游贡献候选

仅记录有具体证据的缺陷或缺失能力；应用自己的适配需求不自动视为上游缺陷。记录不等于已经提交 PR。

每条候选包含：目标项目与版本、现象、最小复现、预期与实际行为、影响、建议修复、验证结果及上游链接。未核实的问题标记为待验证，不能称为已确认缺陷。

目前尚无完成复现的上游缺陷。正在验证 Pi JSON 执行/会话恢复及 Phoenix 公开只读接入；出现问题时先排除本项目适配错误。

## Phoenix: OTLP/HTTP JSON 接收支持（功能候选，未提交）

- 版本：arize-phoenix 20.16.0，Python 3.12.13。
- 复现：认证成功的 SYSTEM key，向 `/v1/traces` 发送 OTLP JSON 与 `Content-Type: application/json`，返回415；同一采集端改为标准OTLP protobuf后可查询到完整span。
- 影响：使用JSON编码的轻量采集器不能直接接入，当前项目已改用protobuf，不阻塞本项目。
- 建议：先与上游确认是否愿意支持JSON编码；若接受，可补充内容协商、JSON转ExportTraceServiceRequest及兼容性测试。
- 分类：能力扩展，尚无证据证明上游承诺支持此格式，不能当作已确认缺陷。提交前需检查重复issue/PR和维护者意向。
- 证据：本项目观测文档记录真实运行版本、415和后续成功结果；复现脚本在忽略的验证目录中，不含可提交凭据。

Pi 暂无已确认上游缺陷。JSON模式stdout接管是适配注意事项，使用继承文件描述符已解决，不自动归类为上游bug。

## Phoenix: 可配置 gRPC 绑定地址（已复现，未提交）

- 版本：20.16.0，Linux x86_64，Python3.12.14。
- 复现：设置 `PHOENIX_HOST=127.0.0.1` 启动，`ss -ltnp` 显示HTTP为127.0.0.1:6006，gRPC为0.0.0.0:4317。
- 原因：`phoenix/server/grpc_server.py` 在TLS与明文分支均固定调用 `[::]:{port}`，没有独立host选项。
- 建议：为gRPC增加可配置host，明确默认行为并提供socket绑定测试。该现象不等于未认证访问成功；验证实例启用了API key认证。
- 本项目约束：采集入口必须仅内部可用。当前部署使用 `scripts/patch-phoenix-bind.py` 针对固定20.16.0将两个绑定改为127.0.0.1；不改权限或认证。升级前需要重新验证，不能无条件套补丁。
- 验证：原实例已在发现通配监听后停止，补丁后已确认6006与4317均绑定127.0.0.1，实际追踪采集与Viewer查询成功；脚本第二次运行返回已应用，未提交上游PR。
