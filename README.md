# Pi Alert Agent

一个常驻 Node.js 服务接收企微告警、管理 Owner 等待流程，并启动独立 Pi 进程调查和修复。每个任务使用业务仓库最新 master 创建的独立 worktree；不同任务互不感知。

规格与任务：[首版规格](https://github.com/lyydsheep/pi-alert-agent/issues/1)。这是正在实现的版本，未经过真实测试群或业务平台验收，不应直接切换生产入口。

## 本地运行

需要 Node.js 24、Git，以及业务仓库的构建工具。安装依赖后，把配置示例复制为被 Git 忽略的本地配置，填写测试群、测试仓库和模型信息。形如 `{"env":"NAME"}` 的配置值从环境变量读取。

```sh
npm ci
cp config.example.json config.local.json
npm run check
npm test
npm start -- config.local.json
```

默认看板只绑定本机，提供只读任务列表。机器人使用官方企微 WSS SDK 入站，群通知使用传统机器人 webhook。不要把本地配置、工作区、日志或密钥提交到公开仓库。

## 群里使用

- `排查 问题描述`：开始独立排查。
- `[告警:来源:事件ID] 告警详情`：以明确事件身份接收，重复通知追加证据。
- 引用方案回复 `同意`、`等一下`、`暂停`、`拒绝` 或 `恢复`；也可使用 `任务 #编号 指令`。
- 无需代码修复的结论回复 `任务 #编号 确认关闭`。

任意告警格式需要配置或接入真实身份解析器，不能根据相似文本合并。当前标记格式是可用的明确事件入口，不代表已适配所有企业告警格式。

现有告警可配置 `intake.source` 和带命名组 `eventId` 的 `intake.eventIdPattern`，从原始文本提取明确告警 ID，无需改变机器人消息格式。上线前需用实际脱敏消息验证该 ID 是否标识同一次事件。`tools` 配置独立查询命令，`skills` 配置私有技能路径；参考 Pi 接入文档，不将企业技能源代码复制进公开仓库。

## 运行边界

任务账本和等待时间持久保存在 SQLite。通知成功后 30 分钟提醒，再等 30 分钟自动执行；延期重置，暂停等待明确恢复。模型会话与任务状态独立保存，主服务始终拥有完成条件的判定权。

首版 worktree 不提供权限沙箱，不强制建设专用 Git 写权限代理。只使用测试仓库验证；Agent 不自动合并、部署或强推。实际 MR API、Agent review 状态名称、必需检查和认证必须按部署环境核实，缺少条件不宣称交付完成。

生产就绪取决于真实模型/查询工具、测试群通知、MR 检查、Phoenix 公共只读、重启恢复及备份恢复的实际验收；本地替身测试不代替这些验收。

Owner 可用“任务 #编号 补充 新信息”保存证据并恢复阻塞任务；暂停任务只保存信息，不自动恢复。MR 平台不可用时任务显式阻塞，恢复后“重试”继续检查原 MR。Pi 返回 externalAction 的结论会阻塞并通知 Owner，不能当作无需代码修复直接关闭。
